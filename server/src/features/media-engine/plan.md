Let's implement a new feature media-engine which will handle uploaded files by users and media generated by the ai.

File structure
---
- Create a repo file where you will define the main functions to interact with the db models mainly assets, assetVariants and generationRequests
- Create a service file where we handle all the logic required to generate a media or handle the upload
- the main index file for endpoints
- Move @audi-generator.ts and media-generator.ts into the media-engine folder [create a dedicated folder]
- Other files depending of your code structure

Endpoints
---
- For image generation: it should handle both text-2-img and img-2-img depending on wheter we passed the image reference url or not.
- Endpoints to generate different type of audio. You can group those that are similar if necessary
- Endpoint to generate video
- Endpoint to retrieve a signed url to the frontend so users can upload their asset directly to GCP cloud storage
- Endpoints to return all the pending generationRequests for a given projectId

Flow
---
1. What happens when we send a request to generate a media using AI
- Our service function get the request, run basic validation 
- We create a generation request instance in our db
- We trigger inngest corresponding event which will send the request, and we return the request Id directly to the client
- When the inngest function finishes successfully - we upload the generated content [url or audio file] to our GCP cloud storage bucket
- Then we update the generation request in the db

Important notes
---
- You need to create the inngest functions needed for all types of media generation
- Use step for inngest functions 
- Inngest step are retried automatically, however, not all failure should be retried, we should retry only when we hit the rate limit or if the service is unavailable [exponentiel waiting]
- After submitting a video request, we need to pool the provider server, handle this with inngest step
- DO NOT assume things, check the docs online if something is unclear
