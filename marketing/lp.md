## Problem

**Headline**
The clip is done. The project is still in five places.

**Body**
The script sits in a document. Stills come from one generator. Clips come from another. Voice is in a third app, music in a fourth, and the cut lives in an editor that has never seen the script.

Each handoff is the same chore. Export the file. Download it. Upload it again. Rename it so you can find it later. Then paste the character description into a new prompt box, because that tool has no idea what you made ten minutes ago.

The tools work. They do not share a project. So the prompt, the reference, and the version that actually matched the scene end up in different places. You spend the session finding the work instead of making the next shot.

---

## Solution

**Headline**
One project for the whole production.

**Body**
Sohizi Lab is the workspace those pieces belong to. You still work with files, folders, documents, and tabs. A script can point at the media it needs. A shot can keep its image, voice line, and notes. The editor can use what you already generated in the same project.

You move from the scene you wrote, to the visuals for that scene, to narration or music, to the cut. The production stays put.

---

## How it works

**Headline**
From the first idea to the final cut.

**Intro**
Four steps. One project.

**1. Write it in the project**
Open a project and put the concept and script where the rest of the production will live.

**2. Generate the media there**
Create images, video, voice, and music for the scene you are on. The files stay in the project.

**3. Build the storyboard**
Break the script into scenes and shots. Keep each asset attached to the moment it belongs to.

**4. Edit in the same workspace**
Assemble the video from the clips, voice, and music already in the project. No download, no re-upload, no second account.

## FAQ

**Headline**
Questions creators ask before they start.

**What is Sohizi Lab?**
An AI workspace for video. You write, generate images, video, voice, and music, organize scenes and assets, and edit the final cut in one project.

**Who is it for?**
Individual creators: AI filmmakers, YouTube and short-form creators, marketers, educators, and anyone producing a video on their own. Team collaboration is not in the current release.

**What can I do in a project today?**
Organize work in files and folders. Write in a text and script editor. Generate images, video, speech, and music. Build a storyboard. Arrange scenes, shots, and assets. Edit the video. Work with an AI assistant that can use the project around the request.

**Does the AI only see my last prompt?**
It can use the wider project: scripts, files, storyboards, scenes, characters, references, generated media, and editing decisions. You still direct it. It does not start from a blank prompt every time.

**Do I have to abandon the tools I already use?**
The core production can stay inside Sohizi Lab, from script to edit. If a specialized step still belongs in another tool, you can export that piece. The point of the workspace is that the project itself no longer has to move with you.

**What kinds of videos can I make?**
Short films, ads, social posts, product videos, explainers, training videos, music videos, branded pieces, and experimental AI work. The workspace is the same. The project is yours.

**Will my character look the same in the next scene?**
Keep the character notes, references, and earlier generations in the project. The assistant and the storyboard can use those when you make the next shot, so you are not describing the character from scratch in a new app.

## Annotations

**Hero.** The eyebrow names the felt chore (exporting a scene into the next tool). The headline is the better state: you can change tools and the project stays. The subhead is the path: the concrete jobs inside Sohizi Lab, plus the reason this workspace is different from a folder of apps. That is the Human Action Model in three beats. The headline also passes the “Now you can” test: now you can move between creative tools without moving your project. It is a real new ability, and it matches the product.

**Problem.** Written in the order a creator actually works, using their objects (script, stills, clips, voice, music, editor) instead of a category label like “fragmented workflow.” No invented time-saved statistic.

**Solution.** One idea: the project is the container. Familiar files and folders stay, so the page does not ask people to learn a new metaphor before they understand the product.

**How it works.** Four steps, each a verb plus an outcome. Step 4 states the handoff that disappears, which is the objection “this will be another place I have to export from.”

**Benefits.** Five outcomes, each tied to a visible behavior. The subscription line is included because the product actually covers those steps. It does not claim a specific dollar savings.

**Differentiator.** Separated from the benefit grid so “all the tools in one app” does not swallow the real distinction: shared project context. The list is jobs the product description already supports.

**Who it’s for.** Three primary paths so a filmmaker, a short-form creator, and a marketer can self-select. The wider list stays short so the page does not become a category index. Alpha scope is stated here in plain language.

**Comparison.** Against the status quo, not against named competitors. Every row is a behavior from the product description.

**FAQ.** Handles “another prompt box,” scope of the current release, team collaboration, existing tools, and character consistency. No guarantee language, because none exists yet.

**Social proof.** Omitted on purpose. There are no customer logos, review counts, or result quotes in the product description. Add a proof bar under the hero only when you have real names and real outcomes. Do not invent them.

**CTA.** “Create your first project” says the action and what they get. Repeated once at the end. If access is still gated, swap both buttons for “Request alpha access” and keep every other line.

## Alternatives

### Headlines

- **Option A: Move between creative tools without moving your project.** Names the exact pain (the project moves) and the outcome (you still switch tools). Clearest match to how creators describe the problem.
- **Option B: Create the video from script to final cut in one project.** Strong if the ad or referrer already promised an all-in-one studio. More literal, less sharp about the handoff.
- **Option C: Your script, your clips, and your edit, in one project.** Concrete objects, easy to scan. Weaker on the AI context that makes the product different.

### CTAs

- **Option A: Create your first project.** Best default. Action plus the thing they leave with.
- **Option B: Request alpha access.** Use this if the product is still invite-only. Honest, and it filters for people willing to try an early release.
- **Option C: Open a project and write the first scene.** More specific, slightly long for a button. Useful as the line under the button if you want the first session to feel obvious.
